# Architecture / 公开审计边界

## 分层

水杯公开审计源码分成三层：

1. **本地核心层**：账本、SQLite、会员状态、消息保护、输入处理；
2. **协议层**：Telegram API 客户端和墨清能力的公开契约；
3. **私有运行层**：生产凭据、真实 API 端点、支付/风控/反诈上游、部署与运维。

第 1 层尽量完整公开，方便审计数据安全与业务正确性。第 2 层公开输入/输出约束，但不暴露基础设施细节。第 3 层不在本仓库。

## 墨清 API 边界

当前公开契约保留以下可审计语义：

- 最多六段查询参数；
- 第一段必填；
- 单段长度限制；
- 非可打印字符拒绝；
- 服务命令不得作为普通查询透传。

真实 HTTP 域名、路由、认证材料、上游 Telegram session 和生产缓存/日志位置由私有运行时注入，不属于公开协议。

## 为什么公开仓不能独立运行

生产机器人需要服务端签发的墨清运行授权和私有能力适配器。公开代码缺少这些组件时默认拒绝启动。即使第三方修改本地门控，墨清后端仍不会向未授权实例提供受保护的服务能力。

## 审计与商业部署是两回事

源码可读不代表获得商业运营授权。公开仓的目标是让安全研究者能够审计实现，而不是交付一份可直接复制运营的生产包。许可边界见 `AUDIT-LICENSE.md`。
